# 反转登记册（Reverse Idea Register）规范与出处

## 一、五个小节的字段

### 1. Inversion Register 反转登记
每条三段：**坏想法**（触发条件 → 后果）／**机制**（这条坏想法背后真正起作用的那条规律）／
**反转对策**（针对机制的对策，不是针对表面现象）。

字段：编号、坏想法、机制、反转对策、证据出处（查了哪个文件/记录/时刻）。

### 2. Novel Standouts 真新对策
现有做法里没有、需要新增的对策。每条写：做什么 + 谁做 + 怎么判定做完 + 不可逆点提示。

### 3. Already in place — but is it?
看起来已经有对策的条目。**关键**：必须回答「已有机制真的覆盖了这个风险吗」。
写清：验证了什么、查了哪里（具体路径/记录/时间）、结论（覆盖／部分覆盖／未覆盖／未验证）。
没查过的一律写「未验证」，不得写成「已确认」。

### 4. Weak-inversion flags 弱反转标记
- 反不过来的：字面取反后没有实际对策。
- 待补事实的：需要查证才能判断（把要查的东西写具体）。
- 已否决的：试过但方案不成立（写否决理由）。

### 5. Decision-ready next step 可执行下一步
最多 3 条。每条 = 做什么 + 谁做 + 怎么判定做完。不要写「建议进一步讨论」。

## 二、强反转 vs 弱反转

强反转 = **提取机制**，不是字面取反。

| 弱反转（字面） | 强反转（机制） |
|---|---|
| 少加一条定时任务 | 派送前查当日是否已投（去重机制） |
| 不要自动化这一步 | 这一步错了不可逆 ⇒ 先影子模式只记录不拦截 |
| 用更好的模型 | 先把流程删到只剩必要步骤，再谈模型 |
| 别做这个提醒 | 提醒要带「该看什么」，否则是噪声（可消费性） |

判定口诀：反转后的对策如果**换个人执行也一样成立**，多半是强反转；
如果它只是把原方案换了个说法，是弱反转。

## 三、与相邻方法的区别（不要混用）

- **premortem**：针对**一个已经成型的具体计划**做「假定它失败了，分析为什么」的复盘。
  产出是失败原因链。本方法产出是**对策**。
- **reversal-test**：只检查**是否被现状绑架**（路径依赖、默认选项惯性），单一维度。
  本方法覆盖更宽（失败机制、最坏版本、删减、不可逆点）。
- **provocation / 挑刺**：给泛泛的反对意见。本方法要求每条反例落到**具体物件/时点/文件**。
- **普通头脑风暴**：发散**好**想法。本方法只生成**坏**想法再反转。

### 4.2 视频承载的核心主张

1. 不要再问「AI 能帮我做什么」，要问「哪些流程根本不该存在」——不是优化，是**删减**。
2. AI 做 0→80%，人做 80→100%。
3. 选对工作流 > 选贵模型。
4. 某流程 AI 介入一周仍没省时间 ⇒ 设计有问题 ⇒ 先删流程再上 AI。
5. 一个起手动作：写下最耗时的三件事，选一件做「≤5 步最简 AI 工作流」
   （AI 做收集/初稿/格式，人做判断/核准），跑通再扩展。
6. 三种形态：传统工作流（剧本固定）／AI 工作流（AI 打辅助）／AI Agent
   （目标导向：感知→记忆→规划→调用工具→行动，闭环）。
7. 同系列另一条（杨竹筠）：做重大决策前，先让 AI 竭尽全力唱反调。
