二、你为什么被叫来做这件事

C 盘上最大的一块冷数据是你自己的历史会话：
C:\Users\Administrator\.minimax\v2\sessions，9,110 个文件，18.03GB，最后写入时间停在 2026-10-26。
昨天 2026-11-11 搬别的冷数据时，MiniMax Code 有 8 个进程在跑，动它会损坏会话索引，所以没动它。今天实测你还有 10 个进程在运行，仍然不能动。这就是它一直留在 C 盘、C 盘腾不出来的原因。

三、唯一允许的写操作：迁 sessions，并留一个入口

前置条件，硬性：执行前先确认 MiniMax Code 进程数为 0。用户会先完全退出程序再发这条。你若在进程还在跑的时候收到这条，立刻停下，回报进程号，不许强搬。

第 1 步，记录基线。
Get-ChildItem -LiteralPath "C:\Users\Administrator\.minimax\v2\sessions" -Recurse -Force -File | Measure-Object Length -Sum
基线应为 9,110 文件、约 18.03GB。数字不符先报出来，不要继续。

第 2 步，整体迁移，用移动不用复制。
目标：D:\C盘搬迁_20261111\MiniMax_历史会话
robocopy "C:\Users\Administrator\.minimax\v2\sessions" "D:\C盘搬迁_20261111\MiniMax_历史会话" /MOVE /E /R:1 /W:1 /NFL /NDL /NP
robocopy 退出码 0 到 7 都算正常，8 以上才算失败。

第 3 步，回读核对，这一步不许省。
Get-ChildItem -LiteralPath "D:\C盘搬迁_20261111\MiniMax_历史会话" -Recurse -Force -File | Measure-Object Length -Sum
文件数与字节必须对上第 1 步的基线，同时确认 C 侧原路径已不存在。对不上就把已迁内容搬回原位，回报失败，不许留半截状态。

第 4 步，在 C 盘原位建目录联接，让你的历史会话照旧可读。
cmd /c mklink /J "C:\Users\Administrator\.minimax\v2\sessions" "D:\C盘搬迁_20261111\MiniMax_历史会话"
建完验证：Get-Item -LiteralPath "C:\Users\Administrator\.minimax\v2\sessions" -Force 看 ReparsePoint 属性，并用 Get-ChildItem 列出条目确认能穿透读到 D 盘内容。
如果联接建不起来，立刻把内容搬回 C 盘原位，恢复成迁移前的状态，再回报失败。宁可不成，不许留下一半。

第 5 步，实测报数。
Get-PSDrive C 读可用空间，报迁移前后的实测值。不要推算，不要按 18GB 估算。
