## 零、给接手方的三条硬前提

**1. 成交是唯一真源。**
浮盈浮亏的基准是「第一笔买入成交价」，
必须从 `/orders` 的已成交记录（status=4）逐笔重建。
**禁止**引用 `/positions` 返回的 costPrice 与 profitPct。
该接口是脏数据，已两次造成误判：
- 2026-09-29 昭衍新药 600488.SH：接口报 +34.67%，真实仅 +8.04%
- 2026-10-13 东岳硅材 300821.SZ：接口报 +73.78%，真实仅 +13.04%

重建不出来时，如实写「浮盈不可用」，**放弃判定**，
不许回落用接口值凑。

**2. 金额不除以 1000。**
`/balance` 与 `/positions` 的金额字段直接就是「元」。
`/orders` 的 currencyUnit=1000 只用于 price 的小数位还原。
官方 mx_moni.py 硬编码除以 1000 是错的，跟着它会错 1000 倍。

**3. 分档取「最严的已命中档」，不是「第一个命中的档」。**
止盈线降序遍历、第一个命中即停；
止损线升序遍历、第一个命中即停。
写反了会导致 -8% / -10% 止损档永远不可达，
ANY 浮亏都只报「-5% 观察」——这正是 2026-10-14 之前的事故。

## 二、仓位规则（2026-10-14 重写）

```
单票上限   总资产 × 25%   ← 锚定总资产，不随可用资金漂移
本批合计   总资产 × 50%
单票下限   总资产 × 15%   ← 低于此不均摊，本批只买 1 只
每日笔数   ≤ 3 笔
现金留存   下单后可用现金 ≥ 总资产 10%
```

**已作废口径：「每笔 ≤ 可用资金 30%」。**
分母错在「可用资金」。账户重仓后可用变少，单笔跟着变小，
形成「越有钱买得越少、越没钱越买不进」的死循环。

实测代价：2026-10-13 松霖科技 603992.SH 只买到 4000 股 = 9.0 万元
= 总资产的 8.46%，而它是当日尾盘封涨停的最强票。
同样的额度按新口径是 19.5 万元 = 总资产 18.31%，可买 8600 股。

**小额度不均摊规则**：本批额度除以只数后，单票低于总资产 15% 时，
不摊成多笔小仓位，只买最强的那一只。
两笔 9 万的小仓位既赚不到波段，又各占一个每日名额。

## 三、建仓规则

### 三条腿互斥，严禁混用

```
--SBQ  首板战法·涨停价排队
       用于「今日首板、当日封板」，在涨停价挂排队等成交
       委托价 = 涨停价

--SBG  首板战法·次日高开买入
       用于「昨日首板、今日高开」，在开盘价附近直接买
       委托价 = 开盘价 × 1.01（不超过涨停价）
       ★ 硬时间窗 09:30–09:47，过了这个点就不是高开买点
       ★ 必须真高开（开盘价 > 昨收），否则该腿不成立

--YJE  一进二战法·接力
       用于「昨日真首板、今日看能否接力」
       委托价 = 现价 × 1.005（不超过涨停价）
       ★ 属另一套系统，与前两条不是同一批样本，不要混
```

**2026-10-12 事故**：远程股份 002692.SZ 是一进二标的，
却按首板战法在 09:51 挂了涨停价，当天开盘 4.98(+4.62%)
才是买点，挂到最高点全天零成交。
**次日高开必须在开盘价附近买，不是等封板再排队。**

### 入选条件（按顺序，不可颠倒）

```
1. 交易日闸门       非交易日直接停，不选股不下单
2. 红线前置过滤     见第五节
3. 三路交叉验证     至少两路同时点名才进候选
4. 实时盘口复核     已封死涨停、当日大跌破位的剔除
5. 2–3 只 → 建仓    少于 2 只不建仓，不凑数
```

**严禁**先按连板高度/涨停排序，再回头验红线。

### 三路交叉来源

```
① 韭研论坛   _daV_vNN_MMDD_0800/1240/1600/2100_forum_11v.md
② 首阳异动   _shyang_collect.py（该源 11:40 才产出，
             09:45 建仓档结构性缺失，如实写「本档缺该路」）
③ 首板涨停分析 _zt_analysis_YYYYMMDD.json
```

落盘文件必须确认是当日日期，日期不符不得当作当日信号。

### 一票否决

```

次新（上市不足 60 天）
```

## 四、止损规则

```
浮亏 5%   观察，记录不动手
浮亏 8%   事件反转或市场不被认可 → 卖一半或全卖
浮亏 10%  无条件全卖                    ← 唯一自动执行档
买入逻辑被破坏  不看浮亏，立即卖
单只仓位 > 35% 且达到目标涨幅 → 被动减仓
```

「止损 12%」是 2026-10-13 的误写，**已作废**，禁止引用。

## 五、止盈规则

```
浮盈 15%  且同时出现「放量滞涨 / 长上影 / 板块退潮」任一 → 卖一半
         ★ 没有形态条件就不卖，只记录
浮盈 25%  涨停打开无法回封 → 全卖
浮盈 30%  无条件全卖                    ← 唯一自动执行档
连板打开 30 分钟不能回封 → 全卖
单只仓位 > 35% 且达到目标涨幅 → 被动减仓
```

**分档是不同动作，不许一律当「触发即全卖」。**
把 15% 读成「无条件全卖」会导致误清仓。

## 六、红线（唯一现行口径，2026-10-13 定案）

```
窗口   往前 10 个交易日，不含该票的启动日（首板当天）
阈值   该板涨跌停幅度 × 80%

       主板 600/601/603/605/000/001/002/003 → 8%
       创业板 300/301、科创板 688/689      → 16%
       北交所 920/8xx/4xx                   → 24%

阳线定义  close >= open 且 当日涨幅 > 本板阈值
一字板    open == close，必须计入，不得豁免
```

**只拦第二条**：窗口内有 1 根超阈值大阳线 → 放行；
有第 2 根才 FAIL。

其他约束：
```
窗口内任一日缺数据 → 记 FAIL，不得因缺数放行
禁止用 abs() 判断涨停
禁止单一 9.9% 阈值
今日这条启动大阳线永远合法
```

**已作废口径**（禁止引用）：
- 2026-10-09 版：主板 6% / 双创北交所 12%，出现任意一条即 FAIL
- 更早四条：5日≤10% / 10日≤24% / 20日≤36% / 无第二根>8%阳线

**任何派生数字（涨幅、累计涨幅）算完必须 dump 原始开收盘字段
核对方向、符号与基准日，不许直接采信上游报告的百分比。**

## 七、执行接口

### 下单只能走脚本，禁止手写绕过

```
建仓  buy_equal.py  A --SBQ|--SBG|--YJE  <code...>
卖出  sell_equal.py A <code> [--half] [--dryrun]
闸门  sell_guard.py <code> A      （只判定，不下单）
账户  acct_check.py               （只读，全账户实账）
止损  stop_loss_run.py A          （全账户扫 + 自动执行全卖档）
```

### 卖出执行链

```
stop_loss_run.py
  → 交易日闸门
  → 账户 accName + uid 双校验
  → /orders 重建成本算浮盈
  → 分档判定（取最严档）
  → 仅「无条件全卖」档调 sell_equal.py
      → sell_guard.py 五道闸（身份/净持仓/成本/合理性/红线）
      → 委托价 = 现价 × 0.995，且不低于跌停价
      → 复核 /positions + /orders
```

五道闸任一不过 → 硬中止，不下单，不降级。

### 自动执行与人工确认的边界

```
自动执行  止损 -10% / 止盈 +30% / 单票仓位>35% 被动减仓
仅报告    止损 -5% / -8% / 止盈 +15% / +25%
          这四档需要形态或事件判断，执行方不越权自动下单
```

## 八、接手方必须知道的五个坑

**1. 分档方向写反。**
`for thr, act in STOP_LOSS: if pct <= thr: break`
从 -5% 开始遍历，任何浮亏都命中「观察」，
-8% / -10% 永远不可达。必须升序遍历 + 第一个命中即停。

**2. 账户字母表与参数解析必须同步。**
sell_equal.py 曾只登记 "C"，传 `A` 时账户字母落进
`elif not a.startswith("--")` 分支被当成股票代码吃掉，
脚本静默退出。新增账户字母后必须逐字母实跑一遍。

**3. 导入路径错误会被 except 吞掉。**
漏把上级目录加进 sys.path → `_trade_day_guard` ImportError
被捕获后按「休市」处理 → 巡检永远不执行且不报错。
**降级处理分支必须打印异常原文**，否则脚本故障会被误读成业务状态。

**4. /orders 的小数位。**
该接口无稳定的 tradePriceDec 字段，历史实现统一用 priceDec。
若改用 tradePriceDec 会把 8.41 读成 84.10。

**5. 涨停池字段名是 thscode，不是 ts_code。**
用 ts_code 取会全部落空，表现为「池子 0 只」。
快照接口不返回股票名，名称只能从涨停池补。
