```
规则B  标题之后紧跟硬分隔符（换行 / 连续短横 / 3个以上空格）

两条都不成立 = 源站存储的标题本身到此为止，保留原样
```

⚠ 详情页 `<title>` 和 `h1` **都是同一个腰斩值**，别去详情页找全文。
⚠ 标题与正文常常只隔一个空格，**不能用「取第一个空格前」当规则**。
⚠ **转义引号 `\"` 会让旧版 `[^"]*` 正则在引号处截断**，

## 五、新风口判定方法论（2026-09-30 立）

**完整内容见** `同花顺首阳异动个股和论坛信息交叉的新风口_判定方法论_20260930.md`

**执行顺序（不可颠倒，四步缺一不可）**：
```
突发新闻 → 连板高度 → 首板扩散 → 论坛跟进
```
**禁止从涨停表反推动机。数据对了框架错了，等于全错。**

**四条标准**：

1. **连板高标（A线）与首板新题材（B线）分开算**
   连板数自己数（逐日涨跌幅按板块限制判定），不信数据源连板字段
   A/B 双线共振 = 真风口；只有一条线 = 不成立

2. **新闻必须突发 + 最新**
   慢变量不算：行业年度会议排期、券商研报、业绩预增、互动易问答、涨价周期
   真风口要两个都占：突发=刚发生意料之外，最新=今天才知道

3. **新冒头 = 论坛和市场新出现**
   必须翻论坛历史验证。连着几天都在聊 = 延续线
   **发帖时间 vs 首封时间相减是必做动作**
   差值 > 0 = 提前信号；差值 < 0 = 扩散，不可当提前信号

4. **同一催化才算一条线**
   同花顺粗分类必须人工拆解，**粗分类相同 ≠ 同一条主线**
   产业链要跨 2 个环节共振，封板时间要集中（不是跨小时散点）

## 八、尺子纪律（2026-10-25 · 系统框与软件工程框同一晚各踩一次 ⇒ 固化）

★ 起因：同一晚双方各自踩了同族坑 —— 脚本**打印的总结句**与**实际扫描到的结果**对不上。
  ⇒ 一句话：**尺子也会错；先怀疑尺子，再怀疑数据。**

① **总结句要再手工数一遍命中**
   脚本说「0 处 / 无不一致 / 无失配」时，另用**另一种口径**复核一遍
   （换目录、换后缀、换计数方式、换实现语言）。
   已知坑：PowerShell `ForEach-Object` 内 `$hits++` **不传回外层** ⇒ 打印假的「0 处」。

② **「0 处 / 不一致」先怀疑尺子**
   已踩过的三种尺子毛病：basename 取错件、0 字节文件被当缺失、
   中文键名 + 独立字段绕过 `key=hex` 赋值形态匹配（东财ut 那次）。

③ **字符数 ≠ 字节数**：一律 `os.path.getsize`。

④ **历史叙述行 ≠ 权威失配**
   登记/更正件里出现的旧指纹，若是**刻意的沿革**（「改之前是哪一版」），属叙述，
   不算权威登记处失配，**不必刷** —— 但要先分清「沿革」与「现役值」两处。

⑤ **指纹不写死**
   重打必然改指纹 ⇒ 登记面/白名单里**写死的指纹天生会过期**，
   而「过期」会被误读成「件被误伤」⇒ 一律写「现算命令 + 路径即判据」。

⑥ **同一轮刷完**
   重打 ⇒ 指纹变 ⇒ 表/戳/登记/补记必须**同一轮**刷完；
   且刷之前**必须有人宣布终版**，否则三方各刷各的、白刷。

⑦ ★ **广播「现值」一律现算；刷之前先查"要不要刷"**
   （2026-10-25 22:3x 事故：同晚同一件 B 包被广播成 4 个不同指纹 ⇒
   两框的队列里同时出现矛盾数字 ⇒ 差点把已对齐的三处刷成旧值）
   ① **对话里转述的数字一律不采信** ⇒ 目标值现算：
      `python -X utf8 首阳工作区\_workspace\pkg_orchestrate.py --print-target`
      （打印现算 b_sha16/bytes/files/sha256 + 各登记处现状 + 「已对齐 ⇒ 不需要刷」）
   ② 刷之前先跑 `--print-target`；**已对齐就别刷**（多刷一行历史 ≠ 更安全）。
   ③ 发现广播的现值与磁盘不符 ⇒ **先发停手令**（别让对方照旧值动手），
      再各自现算一次对齐。

五、执行：每档买入前必须拉当日分时核触板，触板未回封直接剔除，写明触板时间与剔除原因，记入当日炸板回避名单。首板 v4 的"炸板不超过 2 次"是启动日之前的筛池指标，不能给当日炸板背书。

## 第 X+30 条 · 只在启动日当天或启动日第二天买入（2026-11-19 立 · 全聊天框适用）

## 第 X+31 条 · 选股最高优先级：共振点（2026-11-19 立 · 全聊天框适用 · 优先级高于一切选股细则）

用户原话：我四系统里边，最优先的部分是要找到新冒头的题材、概念、主线，其中最核心的启动日可以操作的。或者启动日之后第二天可以操作的核心个股，它将来就大概率会成为龙头，绝对龙头。我要的是这个东西。这是最核心最核心的东西，一切都要以这个为核心！没有共振，没有消息面实质利好，新闻背景消息背景突发和市场情绪共振，都不会出现阶段龙头和阶段热点。

一、最高优先级：首板、一进二、首阳、大智慧 DZH 盘二四系统，一切档位与报告的排序依据只有一条，在新冒头的题材、概念、主线上找到启动日当天或启动日第二天可操作的核心个股，并判断其成为阶段龙头的概率。指标与池子只做入围，不做排序。

二、共振四要素（缺一条即杂毛）：一是真实可查的事件原文，标题日期出处齐全；二是落到公司层面的硬证据，公告纪要订单专利业绩，不是概念标签；三是突发强度够级，产业级、政策级、技术突破级、业绩级，不是媒体复述旧闻；四是市场情绪同向，同事件涨停家数、连板高度、板块跟风、封单与资金承接。

三、判断顺序固定不得倒置：先定性事件重不重要；再看市场认不认，同日同簇几只涨停、有没有连板高标带队、板块是否扩散；再看概念纯正度、可验证性与可持续性，关联必须落到公告或纪要原文；三条同向才叫共振。严禁先看涨幅先看指标先看名单再回头找理由。

四、归因的唯一用途：异动归因与涨停归因写出来是为了找共振点，不是凑字数。核心段必须回答三问——这件事是什么，为什么市场现在追捧它，这只票凭什么当龙头而不是跟风。

五、龙头判据：启动日最新最好今天或昨天；本波位置最低、21 日涨幅在 24% 以内；概念最纯、主营或公告直指事件；资金最深、封单成交额换手同簇领先；有集群、同日同事件至少两只最好有连板高标带队；无公告否认核心逻辑。

六、三指标位置：只负责把票圈进池子，是筛子不是尺子。严禁以命中数量、几列同时成立、重叠个数、同时为 0 作为选股或排序依据，严禁「最高优先组」「重合几只」「三列同时为 0」这类交叉话术。吐息天与严苛天自带滞后，不得拿当天命中情况判个股好坏。

七、执行落点：每档与每份收盘报告，精选栏之前必须先写清当日共振点，哪条事件、哪几只同簇、谁是核心；精选只出核心，其余一句带过；找不到共振如实写「今日无共振点」，不许硬凑。
